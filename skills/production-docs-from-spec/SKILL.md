# 사양서 → 생산관리 가상 문서 11종

제품 사양서 PDF 한 개(여러 개도 됨)를 넣으면, 그 제품을 만드는 가상 공장의 생산관리 문서 11종을 만든다. 값은 사양서에서 가져오거나(무게·치수·센서·전원 등) 사양서로부터 추론하고, 사양서에 없는 것(수량·날짜·작업자·비가동 등)은 그럴듯한 가상 값으로 채운다. 모든 값의 근거는 정답 csv 의 `basis` 칸에 남는다.

이 문서들은 **실제 한화비전 생산 데이터가 아니다.** 파서·온톨로지 변환을 시험하기 위한 가상 데이터다. 사용자에게 결과를 알릴 때도 이 점을 분명히 한다.

## 실행

생성기는 이 스킬 폴더의 `scripts/` 에 있다. 스킬 폴더 경로를 `<SKILL>` 이라고 하면:

```bash
python <SKILL>/scripts/spec_to_production.py "<사양서.pdf>"
```

- 저장 위치: 지정하지 않으면 **지금 위치**에 `생산관리문서_<모델명>` 폴더를 만든다. 사용자가 원하는 곳이 있으면 `--out <폴더>`.
- 여러 PDF 를 한 번에 넣으면 한 공장에서 같이 만드는 것으로 보고 한 세트를 만든다 (폴더 이름 `생산관리문서_<첫 모델>_외N`).
- `--formats`: xlsx 말고 더 낼 형식 (작업실적 제외 10종에 적용). 기본은 `pdf,docx,hwpx`. 빈 값(`--formats ""`)이면 xlsx·csv 만.
- `--category network|analog|vpm`: 제품군을 직접 정한다. 안 주면 폴더 이름(`네트워크 카메라`·`아날로그 카메라`·`VPM`), 그다음 사양서 글(AHD/TVI/CVI, VPM 표시)로 정한다. 지금 생성기는 제품군을 문서 내용에 쓰지 않고 `사양추출.json` 에 기록만 하므로, 틀려도 문서는 같다.
- `--seed N`: 같은 사양서로 다른 가상 값 세트를 만들고 싶을 때. 같은 번호면 언제나 같은 결과다.

한 번 실행에 10초 안팎(PDF 변환 포함)이 걸린다.

### 실행 전 확인

- 파이썬 패키지: `pip install pdfplumber openpyxl python-docx pymupdf`. 없으면 생성기가 무엇을 설치할지 알려 주고 멈춘다.
- PDF 를 만들려면 LibreOffice 가 필요하다. 없으면 PDF 만 건너뛰고 경고를 띄운다 (xlsx·docx·hwpx 는 그대로 만든다). 설치 위치가 특이하면 `SOFFICE` 환경변수에 `soffice` 경로를 적는다.
- 넣는 파일은 **글자가 들어 있는 제품 사양서**여야 한다. 시험성적서·브로셔 일부·다른 회사 문서·스캔 이미지는 생성기가 이유를 말하며 거절한다. 거절 문구를 그대로 사용자에게 전하고, 다른 PDF 를 받으면 된다. 거절을 우회하려고 코드를 고치지 않는다: 사양서가 아닌 문서로 만든 생산 문서는 근거가 없다.

## 결과 확인과 보고

생성기는 끝에 스스로 검사(verify)를 돌리고 `검증 오류 없음` 또는 `검증 오류 N건` 을 출력한다. 검사 내용은 원본 xlsx ↔ 정답 csv 줄 수, 문서 사이 키·수량·일정·날짜 연결, 사양서 기준값, 원본에 근거 꼬리표가 새지 않았는지, 그리고 PDF·docx·hwpx 표 칸이 xlsx 와 같은지다.

- `검증 오류 없음` 이면 사용자에게 결과 폴더, 만들어진 문서 수, 출력된 요약 줄(품목·BOM·공정·지시 수 등)을 알린다.
- 오류가 있으면 출력된 오류 줄을 그대로 보여 주고, 결과를 "완성"이라고 말하지 않는다. 같은 사양서에서 다시 나는 오류라면 생성기 문제이므로 사용자에게 알린다.
- 사용자가 모양을 보고 싶어 하면 BOM·품목마스터 등의 PDF 를 열어 보라고 안내한다. hwpx 는 한글 프로그램에서 열린다.

보고할 때 짧게 덧붙일 것:
- 수량·날짜·작업자·비가동 같은 값은 **가상**이다. 어떤 값이 사양서에서 왔는지는 각 문서의 `_정답.csv` 의 `basis` 칸에서 볼 수 있다: `[사양서 p.N]` 사양서 그 쪽에 그대로 있음, `[사양서 추론]` 사양서 값에서 끌어냄, `[가상]` 근거 없이 정함.
- `_원본.xlsx` 는 현업 ERP·MES 에서 내려받은 모양이라 근거 표시가 없다. 파서 시험의 입력은 원본, 채점 기준은 정답 csv 다.

## 만들어지는 것

폴더마다 `<문서>_원본.xlsx` 와 `<문서>_정답.csv`. 작업실적을 뺀 10종 폴더에는 `_원본.pdf`, `_원본.docx`, `_원본.hwpx` 도 있다 (같은 xlsx 에서 만들어 값이 같다). 맨 위에 `사양추출.json` (사양서에서 읽은 값과 제품군 판단 근거).

문서별 칸과 시트 구성, 문서 사이 연결은 `references/documents.md` 에 있다. 사용자가 특정 문서의 칸이나 의미를 물을 때 읽는다.

## 하지 않는 것 (지금 단계의 범위)

- 입력은 **제품 사양서 PDF 만** 쓴다. 한화비전 포털의 시험성적서·매뉴얼·인증서·펌웨어 이력도 생산 문서를 더 실제처럼 만들 수 있지만, MVP 단계에서는 넣지 않기로 했다. 사용자가 원하면 그 점을 알려 주고, 바로 코드를 바꾸지 말고 먼저 상의한다.
- PDF·docx·hwpx 는 작업실적을 뺀 10종에서 낸다. 작업실적은 머리글이 2줄이고 칸이 병합된 일지 양식이라 변환기(`production_export.py`)가 아직 못 읽어서 xlsx·csv 만 있다. 넣으려면 변환기가 병합·2줄 머리글을 읽게 고친 뒤 `scripts/spec_to_production.py` 의 `EXPORT_DOCS` 에서 제외를 풀어야 한다.
- 실제 회사 양식을 흉내 내지 않는다: 회사명은 `(주)가상전자 · 생산1공장` 이고, 양식 칸은 공개 자료(ISA-95, 국내 ERP 교재, 오픈소스 ERP 등) 조사로 정한 것이다.
