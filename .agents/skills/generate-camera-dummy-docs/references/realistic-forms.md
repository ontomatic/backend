# 부서별 양식

## 공통

문서번호·개정·작성일·대상 모델·제품코드·작성/검토/승인을 넣는다. 같은 문서번호·개정에 상충하는 단일 제품 사양을 부여하지 않는다. 담당자·공급처는 가상으로 만들고 실제 서명·인증 로고처럼 꾸미지 않는다.

개발 입력 → 설계 변경 → 펌웨어 배포 → DVT 시험 → 품질 검토 → 양산 이관 → 초도 생산 → 출시 날짜를 맞춘다. 출시 후 변경 사례면 그 사실을 명시한다. 부품·검사·릴리스마다 한 행의 표를 사용하고 검토 이유는 자연스러운 문장으로 쓴다. 페이지 수를 억지로 고정하거나 결재란만 별도 페이지에 남기지 않는다.

## 요구사항

설치 장소·관제 목적·제약을 제품 유형에 맞게 쓴다. 영상/광학, 전원/연동, 환경/기구, 전용 기능을 나누고 요구 ID·수락 기준·시험 ID·담당·우선순위의 검증 매트릭스를 둔다.

센서·렌즈·화각, 전원별 공급 가능한 전력, 환경 등급의 적용 범위를 검토한다. 피쉬아이의 광학 화각과 천장 설치 시 방위각 커버리지를 구분한다. PTZ, 열화상, 방폭, 멀티센서, 인터콤의 전용 속성을 반영한다.

## BOM

No.·품번·품명·규격·대당 수량·단위·Rev.·공급처를 부품당 한 행으로 만든다. 기본 센서·렌즈·메인보드·하우징·전원보드에 제품 구조를 반영한다. 열화상에는 열 센서/통합 모듈, PTZ에는 구동부, 인터콤에는 오디오·버튼을 고려한다. 사양이 다른 부품에 같은 품번을 쓰면 동일 부품 지원 모드의 차이인지 설명한다.

ECR/ECN, 변경 전후, 이유, 적용 LOT, 기존 재고 처리와 초품 확인을 연결한다. 실제 CAD를 만들지 않았으면 도면 메타데이터와 이력만 있다고 알린다.

## 펌웨어

대상 보드·HW Rev., 배포 버전·빌드·배포일·이슈·변경 내용·승인·롤백 버전을 넣는다. 아날로그에 네트워크 기능을 일괄 추가하지 말고 ISP 제어 등 적절한 펌웨어로 표현한다.

SBOM은 구성요소·버전·용도·라이선스·공급 주체를 기록한다. 가상 패키지를 표시하고 바이너리 없는 시험용 해시를 실제 파일 해시라고 하지 않는다. 업데이트·동작 확인·복구 절차를 적는다.

## 품질

시료 LOT·일련번호·수량·기간·담당·장비·교정 유효일을 넣는다. 검사표는 항목·조건·기준/허용범위·측정값·단위·판정·비고로 구성한다.

상한 시험과 시험 인가 조건을 구분한다. 낙하 높이가 낮다고 무조건 합격으로 계산하지 않고 적용 높이와 시험 후 기능을 함께 확인한다. IR 없는 제품에 IR 최대 부하 조건을 일괄 기재하지 않는다. 가속도 g0와 무게 g를 구분한다.

불합격은 NCR·격리·원인 확인·재시험일·종합 판정과 연결한다. 의도적 문서 충돌과 불합격은 다른 라벨로 둔다. 가상 인증 관리번호를 실제 취득 번호로 주장하지 않는다.

## 생산

작업지시·라인·LOT·착수일·계획 수량·사이클·도면/FW·담당·초품 수량·조립 조건을 넣는다.

자재표는 품번·품명·대당 소요·순소요·예비·가용 재고·판정으로 구성한다. 순소요=계획수량×대당소요, 예비=ceil(순소요×계획예비율)로 계산하고 정의를 적는다. 가용재고<순소요+예비이면 부족이다. Excel 수식 사용 시 실제 계산과 저장 결과를 확인한다.

설계·개발·생산·품질·자재별 체크리스트를 둔다. 불합격·필수 준비 미완료가 있으면 보류와 해제 조건을 명시한다. 전부 완료인데 이유 없이 보류하지 않는다.
