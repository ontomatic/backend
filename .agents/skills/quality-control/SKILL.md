# 품질관리 D안 실행 프롬프트 작성

이 스킬의 산출물은 **실행 가능한 프롬프트**다. 사용자가 별도로 실행을 요청하지 않은 한 품질관리 데이터 생성이나 Drive 업로드를 시작하지 않는다.

## 순서

1. 사용자가 지정한 입력 파일, 제품군 매핑, 결과 위치, 참고 문서를 확인한다. 파일을 실제로 열지 않았다면 그 내용이나 사양을 확인한 것처럼 쓰지 않는다.
2. 파일별로 모델명, 제품군, 문서명·버전, 사양값, 측정 조건, 페이지·표·셀 위치를 추출해 근거 목록을 만든다. 파일에 없는 사양은 생성 대상 항목에서 제외한다. 불명확하거나 충돌하는 값은 두 위치를 모두 기록하고 더 구체적인 측정 조건이 붙은 값을 우선 적용하도록 프롬프트에 지시한다.
3. `references/qc_contract.md`의 10종 스키마와 결함 규칙, `references/d_style.md`의 출력·디자인 계약을 적용한다. 원래 스킬의 특정 모델 5개 고정 목록은 새 입력에 적용하지 않는다.
4. `execution_prompt.md`의 입력 칸을 실제 확인한 정보로 채워 새 실행 프롬프트를 작성한다. 이 파일은 10종 스키마를 본문에 포함하므로 프롬프트 한 파일만 복사해 사용할 수 있다. 아직 확인하지 못한 입력은 `{{확인 필요: ...}}`로 표시하고 추정값으로 대체하지 않는다.
5. 작성한 프롬프트를 다음 항목으로 자체 점검한다: 10종 분리, 종별 4개 확장자, HWPX 명시, 문서 간 동일 데이터, vendor/synthetic 구분, 페이지 근거, D안 표지·표·결재, 결함 로그, 재검증, Drive 업로드 조건.

## 프롬프트에 반드시 넣을 지시

- 한 입력 파일에 모델이 여러 개 있거나 여러 파일이 한 모델을 설명하면 모델별로 근거를 합치되, 서로 다른 모델의 사양은 섞지 않는다. 제품군은 파일명만으로 단정하지 말고 원본과 사용자가 지정한 매핑을 따른다.
- 원본에서 확인한 제품 사양만 `vendor` 근거로 사용한다. LOT, 검사일, 담당자, 협력사, 고객사, 판정 및 측정값은 `synthetic`이다. 합성 문서 전체의 행 `origin`은 `synthetic`으로 쓰고, 사양 기준의 원본 근거는 비고 또는 별도 근거 목록에 명시한다.
- 결과는 제품군/문서종류/문서종류_원본.{hwpx,docx,xlsx,pdf} 구조로 만든다. 10종을 한 문서에 합치지 않는다. 1개 제품군당 핵심 파일은 40개다. 한글 파일은 반드시 `.hwpx`다.
- 네 형식은 같은 문서의 동일한 행·수치·판정·근거를 담는다. DOCX·HWPX는 편집 가능한 텍스트·표를 사용하고, PDF는 시각적 배포본, XLSX는 원본 스키마와 계산식을 보존한다. 단순 이미지를 문서 본문으로 붙인 파일은 허용하지 않는다.
- 승인된 D안은 제목·문서번호/버전/작성일 메타데이터, 모델/LOT/검사수량 요약, 특성별 검증 표, 결재란, `합성 데이터` 안내를 갖춘 실무 문서다. 색만 바꾼 변형을 D안으로 간주하지 않는다.
- 원래 스킬의 결함 주입은 검증 목적의 합성 데이터에만 적용한다. 결함마다 생성과 동시에 행ID·종류·설명을 로컬 검증 로그에 기록한다. 최종 전달 폴더의 40개 핵심 파일 구조를 바꾸지 않도록 검증 로그는 별도 작업 폴더에 둔다.
- 출력 전 `scripts/validate_output.py`로 폴더·확장자·XLSX 헤더를 확인한다. 이 구조 검사 통과만으로 완성 판정을 내리지 않는다. PDF와 DOCX를 실제 렌더링해 한글이 보이는지 확인하고, HWPX는 가능한 한컴오피스에서 직접 열어 편집 가능 여부를 확인한다. 검증표의 모든 vendor 항목에 실제 원본 페이지를 표시하고, `합성 데이터` 안내가 각 문서에 있는지 확인한다. 원본과 사양 근거도 대조한다. 실패하면 납품/업로드를 보류하고 원인·남은 검증을 보고한다.
- Drive 업로드가 요청되면 먼저 로컬 결과와 Drive 대상 구조·중복 파일을 확인하고, 업로드 후 파일 수와 경로를 대조한다. 업로드 요청이 없으면 프롬프트만 작성한다.

## 참고 자료

- `references/qc_contract.md`: 원래 스킬의 10종 컬럼 및 결함 주입 규칙.
- `references/d_style.md`: 승인된 D안의 파일 구조와 문서 표현 규칙.
- `execution_prompt.md`: 새 입력에 맞춰 채우는 독립형 실행 프롬프트.
- `scripts/validate_output.py`: 생성 결과 구조와 XLSX 스키마 검증기.
