# 미사용 카메라 데이터시트 2건 검증 결과

| 모델 | 원본 | D안 기존 사용 모델과의 차이 |
|---|---|---|
| XNO-8080R | [네트워크 불렛 데이터시트](https://drive.google.com/file/d/13wWwZF8t7Wmc3bjVEawBZkKTV0_PV-9A/view) | 기존 네트워크 불렛은 PNO-A9081R |
| HCD-6080R | [아날로그 돔 데이터시트](https://drive.google.com/file/d/1EHSqKOI2A5lai0xAtrinY0kdCSF6NC94/view) | 기존 아날로그 돔은 HCD-6010 |

두 원본의 전문 텍스트를 읽고 새 프롬프트의 입력별 근거 목록을 작성했다. 파일명만 보고 값을 채우지 않았다.

## 사양 대조 사례

- XNO-8080R: 2쪽 Specifications의 2560x1920, 광학 2.5x, 컬러 0.07Lux/흑백 0.007Lux(1/30초, 30IRE), 4쪽 IP66/IP67/IK10 및 -40°C~+55°C를 사용했다. 1쪽 요약의 `0Lux (IR LED On)`은 다른 조명 조건으로 기록했다.
- HCD-6080R: 2쪽 Specifications의 1920x1080, 광학 3.1x, 컬러 0.11Lux/흑백 0.011Lux(1/30초, 30IRE), 3쪽 -10°C~+55°C를 사용했다. 원본에 IP/IK 등급이 없어 검사항목에서 제외했다.

## 실행 및 판정

| 항목 | 결과 |
|---|---|
| 입력별 실행 프롬프트 2개 작성 | 통과 |
| 제품군별 10종 분리, 각 `.hwpx/.docx/.xlsx/.pdf` | 2제품군·20종·80파일 구조 검사 통과 |
| XLSX 헤더·행ID·origin·원본 사양, 결함 로그·행ID | 자동 대조 통과 |
| 네 형식의 행ID 및 PDF/DOCX 합성 안내 | 자동 대조 통과 |
| PDF 한글·D안 표 구성 | 렌더링 확인 |
| DOCX 한글 시각 검사 | **미통과**. 번들 DOCX 렌더러 출력에서 한글 글리프가 표시되지 않음. DOCX 내부 편집 가능한 텍스트에는 한글이 들어 있음. 폰트를 바꿔 재시도했지만 동일. |
| HWPX 한컴오피스 직접 열기·편집 | **미검증**. ZIP/XML 구조와 텍스트 미리보기만 확인. |

**최종 판정: 프롬프트 생성과 사양 추출·파일 구조는 검증됐지만, 4형식 완성품의 합격 판정은 보류.** 특히 DOCX의 한글 시각 확인과 HWPX의 실제 앱 열기 검사가 남아 있다. 이 시험 결과는 Drive에 업로드하지 않았다.

## 재현 방법

ZIP을 풀어 `qc-d-style-prompt-builder` 폴더에서 실행한다. Python 환경에 `python-docx`, `openpyxl`, `reportlab`, `pypdf`가 필요하다. 이 검증용 렌더러는 macOS의 Arial Unicode 글꼴 경로를 사용한다. 두 원본 PDF는 ZIP에 복제하지 않았고 위 Drive 링크와 확인한 근거 목록을 사용한다.

```bash
python validation_two_sources/make_prompts.py
python validation_two_sources/build_validation.py
python examples/validate_output.py validation_two_sources/result_D
python validation_two_sources/check_content.py
```

생성된 `result_D`는 시험 파일이며 최종 납품/업로드 대상이 아니다. 시각 검사는 별도로 수행한다.

## 반영한 스킬 수정

구조 검사만으로 성공을 선언하지 않도록 했다. vendor 사양의 행별 페이지 근거, 합성 데이터 안내, DOCX/PDF 한글 렌더링, HWPX 앱 검증을 명시적 합격 조건으로 추가했다. 검증 실패 시 업로드를 보류하도록 했다.
